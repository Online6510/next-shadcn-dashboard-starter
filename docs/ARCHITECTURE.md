# Архитектур

```text
Next.js App Router → серверийн өгөгдлийн давхарга → SQLite
React форм → Server Action → Zod → SQLite гүйлгээ → шинэчлэгдсэн хуудас
Газрын каталог → хайлт, хөтөлбөр, координатын зураг
```

## Өгөгдөл

`src/features/wanderly/catalog.ts` газрын нэр, аймаг, төрөл, зураг, координатыг тодорхойлно. `model.ts` аялал болон доторх зогсоол, зардал, тэмдэглэлийн төрлийг тодорхойлж, формын утгыг шалгана. Огноог `YYYY-MM-DD` хэлбэрээр хадгална. Өдрүүдийг эхлэх, дуусах огнооноос гаргана. Аяллын төлвийг Улаанбаатарын огноогоор тооцно.

SQLite-ийн `trips` хүснэгт нэг аяллыг JSON баримт болгон хадгалдаг. `db.ts`-ийн засвар нэг `BEGIN IMMEDIATE` гүйлгээнд уншиж, шинэчилж, хадгална. Ингэснээр нэг аяллыг зэрэг засах хүсэлтүүд өөр өөр хувилбарыг дарж бичихээс хамгаална. Аяллыг устгахад түүнд хамаарах баримтууд хамт арилна. `metadata` хүснэгт эхний seed хийснийг тэмдэглэнэ.

Энэ бүтэц цөөн аялалтай локал демод тохирно. Том өгөгдлийн сан, хэрэглэгч бүрийн хандалтын эрх, хэвийн болгосон хүснэгтүүд шаардлагатай үед өгөгдлийн давхаргыг солих боломжтой.

## Хуудас ба тооцоо

- `/` болон `/explore` нь каталогийн мэдээллийг уншина. Хайлтыг браузерт хийдэг.
- `/trips/[id]` огнооноос өдрүүд үүсгэж, тухайн өдрийн зогсоолуудыг хадгалсан дарааллаар харуулна. Цэг болон зогсоол нэг ID-аар сонгогдоно. Газрын зураг нь орон нутгийн вектор өгөгдөл ашигладаг. Цэгийн дэлгэрэнгүйгээс OpenStreetMap руу холбоостой.
- Төсвийн үлдэгдэл = нийт төсөв − бодит зардал. Зогсоолын төлөвлөсөн дүнг тусад нь нийлбэрлэнэ.
- `/journal/[id]` тэмдэглэлүүдийг огноогоор эрэмбэлж, зураг томруулахдаа браузерын `dialog` ашиглана. Гадаад зургийг серверийн проксигоор татахгүй.
- `actions.ts` нь өөрчлөлт бүрт серверийн шалгалт хийдэг. Хугацаа солиход аяллын шинэ хязгаараас гадуур зогсоол үлдэхийг хориглоно.

## Дүрэмт санал

`planner.ts` нь сонгосон аймгаар шүүж, сонирхолд тохирох газруудыг эхэнд эрэмбэлнэ. Нэг өдөрт нэг аймгийн, хэмнэлээс хамааран 1–3 зогсоол сонгоно. Нийт зогсоолын тоонд төсөв бүрийн 60,000 ₮ тутамд нэг зогсоол байхаар, доод тал нь нэгээр хязгаар тавина. Төлөвлөсөн зогсоолуудад төсвийн 35%-ийг тэнцүү хуваарилна. Энэ нь аппын дүрэм бөгөөд тухайн газрын үнэ, замын хөдөлгөөн, зорчих хугацааны мэдээлэл агуулахгүй. Хэрэглэгч саналаа урьдчилан харсны дараа хадгалж, зогсоол бүрийг гараар засаж болно. Сервер хадгалахаас өмнө саналыг шалгаж дахин тооцно.

## Төслийн эх загвар ба шинэ хэсгүүд

Next.js App Router, Bun, TypeScript, lint тохиргоо болон Tabler дүрсний бүртгэл эх загвараас ирсэн. Wanderly-ийн харагдац, каталог, аяллын форм, газрын зураг, төсвийн тооцоо, дурсамж, SQLite хадгалалтыг энэ төсөлд шинээр хийсэн.
